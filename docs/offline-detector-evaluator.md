# SPAIS offline detector evaluator (reference CLI)

This tool evaluates **precomputed detector outputs** against labelled holdout boxes for a registered threshold candidate. It is a deterministic evaluation helper, not a model-training service and not an inference engine.

## Supported scope

- Candidate status must be `evaluation_pending`.
- Candidate `changeType` must be `thresholds`.
- The artifact is a small JSON threshold configuration with `schemaVersion: 1`, `confidenceThreshold` and `iouThreshold`, each in `[0, 1]`.
- The evaluation bundle is a JSON file with `schemaVersion: 1` and a `samples` array. Each sample has a unique `id`, `groundTruth` boxes, and candidate-pipeline `predictions`.
- Coordinates are normalized to `[0, 1]`; boxes include `className`, `x`, `y`, `width`, `height`. Predictions also include `confidence`.
- A greedy, confidence-sorted match counts a true positive when class names match and IoU meets the artifact threshold. Unmatched predictions are false positives; unmatched labels are false negatives.
- `falsePositiveRate` is defined as the fraction of evaluated images containing at least one unmatched prediction. This is an operational metric, not a universal statistical false-positive-rate definition.

## Run

```bash
node tools/offline-detector-evaluator.mjs \
  --candidate ./candidate.json \
  --artifact ./threshold-candidate.json \
  --dataset ./holdout-bundle.json \
  --private-key ./evaluator-private.pem \
  --output ./signed-evaluation-report.json
```

The candidate manifest may be either a candidate object or the API response shape `{ "candidate": ... }`. The tool hashes the exact artifact and dataset bytes and refuses to sign if their digests do not match the registered candidate. The private key must be RSA with at least 2048 bits; on POSIX systems the private-key file must be owner-only (for example `chmod 600 evaluator-private.pem`). The output file is created with owner-only permissions and is not overwritten.

Without `--output`, the signed report JSON is written to standard output and a summary is written to standard error. The CLI makes no network requests. Submit the report separately to the authenticated evaluator API using a service principal with `model:evaluate`.

## Trust boundary

The tool does not run inference. The `predictions` in the holdout bundle must have been generated by the candidate model/pipeline in the trusted evaluator environment; otherwise a signer could attest to fabricated predictions. Keep labelled holdout data and private keys in an isolated, access-controlled evaluation environment. The server verifies the signature, checks the candidate and dataset digests, and computes pass/fail from configured thresholds, but it cannot independently prove how predictions were generated.

A passing report only means the signed metrics met the configured policy. The system does not activate the candidate, deploy shadow/canary models, change production inference, or automatically roll back a model. Those remain separate future gates.
